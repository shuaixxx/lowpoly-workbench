# 四集合模板与对象合并约定

来源：用户提供的集合截图及 2026-10-28 的明确更新要求。此规则描述模板的使用方式；实际文件及对象清单须在每个项目中读取，不把截图当作已检查的网格证据。

当前项目的文件名为 `模板.blend`，从项目工作目录定位。先核对磁盘保存版本中的集合与截图/约定是否一致；文件只有这个名字不代表内容已经更新。若已打开场景与磁盘文件不同，分别记录文件路径和保存状态。

## 集合职责

| 集合名 | 用途 | 制作时读取 |
|---|---|---|
| 高模 | 查看完整物体关系、遮挡与拼合关系，理解结构，并作为形体参考。 | 部件对应关系、原始形体、变换和参考位置；总览高模是否合成一件不自动覆盖工作部件的对象划分。 |
| 前后对称 | 理解该组部件的前后对称安排。 | 对称方向、平面、原点、现有修改器或示范对象，以及参与对称的单元；不只凭“前后”指定某条世界轴。 |
| 四向对称 | 理解该组部件的四向重复安排。 | 旋转复制或双轴镜像的实际方式、中心、方向、基础单元和连接边界；不把“看起来四向”当作完整制作参数。 |
| 自行判断 | 对未给定这两种对称安排的部件，结合结构判断。 | 是否需要对称、如何分配几何、哪些特征应保留，并记录依据；不改变用户已经给定的对象拆分。 |

集合表达工作用途或对称安排；**合并与分开由对象层级表达**。需要检查隐藏对象及子集合，同一个 Object 被链接到多个集合只计一次；若同一对象同时落入冲突的对称安排，先定位冲突，不重复制作或任意选一项。

实际模板中已有的明确安排优先于历史碑形资产示例。名称与内容不符、轴或中心无法确定时，只报告具体缺失，继续其他可确定的部件。

## 对象边界决定低模边界

读取模板中明确用于该部件制作安排的对象身份与归属，建立“来源对象 → 低模对象”对应关系。高模总览、旧版低模和对称示范副本需要先匹配角色，不能混在一起计数。

| 模板中的情况 | 低模结果 |
|---|---|
| 两块几何已经合成同一个 Object | 制作在同一个低模 Object 中。即使来源包含多个不连通网格岛，也不因此拆成多个低模对象。 |
| 两个独立 Object 接触、交叠或完全重合 | 保持两个低模对象，不因空间接近而合并。 |
| 两个 Object 同属一个集合、具有父子关系或共享 Mesh 数据 | 仍是两个对象，保持分开。 |
| 一个 Object 同时链接到多个集合 | 仍是同一个对象，不重复生成。 |

“合并”在此指对象组织。是否焊接顶点、连接面环、布尔融合或删除内部面，还须依据形体、着色、后续用途和明确要求另行判断。不能因对象已经合并就自动焊接所有相交处，也不能为追求一个连通分量而改变原形体。

制作中允许使用临时辅助对象，交付前恢复约定的部件归属。对称副本要记录其来源单元，不把生成副本误认为用户新增的独立部件，也不因对称操作把原本独立的两个部件合并。

`自行判断` 允许判断制作方法，不允许覆盖“同对象合并、不同对象分开”。同样，自动诊断建议、性能优化或案例中的连接方式不能自行覆盖此项目约定。

## 记录与验收

- 保存模板版本、来源对象身份、集合路径、对称参数/来源单元、目标对象对应表。名称用于展示和定位，不能只凭相似名称认定两个对象相同；跨版本需要重新核对映射。
- 保存局部案例时，在 `provenance` 中记录来源对象与集合、对称上下文、对象分组约定。面片只是局部样本，面片独立保存不代表整个部件可以拆开。
- 交付时检查有没有跨来源对象误合并、把同一来源对象误拆分、重复生成，以及对称接缝/连接问题。排除参考对象和临时辅助对象后检查实际制作对象。
- 当前版本将这些规则加入制作与人工验收流程；尚未提供自动读取模板、自动推断对称参数或自动检查全部对象映射的完整执行器。已有 `blender_bridge` 和案例索引不能冒充这些检查已经完成。
