# 低模几何制作与案例积累

## 已明确的项目约定

以下是对项目中用户明确要求的整理，不是从合成试验推导的结论：

- 用户从全局标定重要区域；采用独立顶点组 `lp_importance`，范围 0–1。AI 不用高度、人物距离或名称猜测权重。未赋值是未知，不等于 0。
- 本阶段处理低模几何，考虑后续烘焙的可行性；UV、实烘焙、贴图和引擎交付由后续明确范围决定。
- 编辑源尽量保持四边面，预算按修改器计算后的实际三角面统计。
- 碑形资产案例的目标为 8,000–10,000 三角面，不含原高模、铁链和人物；主体四向旋转，顶部熊按 Y 轴镜像。碑身使用包含完整主平面和完整转角面的单元。它们是案例参数，不是其他资产默认值。
- 同类结构的倒角保持一致，保留原高模和参考低模，修改写入新版本。

其中权重的含义已经确定；“权重怎样数值映射为局部面数”尚未确定，也没有实现整件预算求解器。不得把 0.8 权重直接解释成 80% 的面数或自动代替必要特征保护。

## 1. 建立项目简报

记录目标部件、静态/变形用途、软件版本、已有网格、排除对象、实际镜头、预算口径、对称要求和允许修改范围。读取场景状态，保存来源版本。用户未给出的阈值保留为空，先做不依赖它的检查。

规则入口为 [LP-001–LP-016](../skills/lowpoly-workbench/references/lowpoly-stage-rules.md)。来源档案中的指令不自动生效；以当前用户范围、项目参数和本阶段规则为准。

## 2. 用户标定重要性

在编辑网格上建立空的 `lp_importance` 通道，让用户绘制。通道中每个顶点的未赋值状态和显式 0 分别保存。曲率、轮廓和连接特征可以单独保护，不能覆盖人工的重要性。

拓扑变化后，旧顶点编号失效。映射权重时保存映射来源，并请用户核对重要区域；没有可靠映射就报告缺失。

## 3. 提出局部问题并检索

选择一个真实面片，例如“这个 16 点边界要过渡到 8 点，且不改变石柱外沿”。导出局部网格和世界变换，标明用途、对称、边界和权重来源。

先筛选案例状态、用途、边界环和面类型，再按粗略形状描述排序。需要保持边界点数时启用边界锁定。当前边界锁定只筛选点数，不建立点对点对应；候选仍需检查朝向、尺度、连接与特征位置。

默认查询只用 `accepted`。`unreviewed` 可用于探索，`rejected` 或 `failed` 用于回顾失败原因；它们不能混入生产推荐。拓扑指纹只帮助筛选/去重，不是图同构证明或质量分数。

## 4. 制作候选并分层检查

先在局部副本验证，保留修改前的源网格。Scenario 可构造环线、管状块及疏密过渡；没有合适模板就记录为探索性制作。检查剪影、结构边、倒角、局部着色和连接，再检查整体预算。

| 层级 | 记录内容 | 不能据此推断 |
|---|---|---|
| 代码与数据 | 格式、索引、null/0、状态筛选 | 网格视觉合格 |
| Blender 运行 | 控制面/实际三角面、部分几何诊断、文件重开 | 所有规则均已自动验收 |
| 视觉 | 同视角轮廓、线框、中性光、局部接缝 | 用户已认可 |
| 用户评价 | 接受/拒绝、范围、原因和证据 | 用户认可了代理的全部解释 |
| 后续阶段 | 实烘焙、UV、引擎运行 | 未做的阶段已经通过 |

## 5. 保存案例、评价与候选规则

JSON 网格是案例事实来源，SQLite 是可重建索引。保存修改前后两个不同 ID，并记录关联；不要覆盖历史。案例评价需要用户身份标记和评价证据，但程序只能检查字段齐全，不能认证用户身份或证明评价真实。

`accepted` 只表示这个案例在记录的范围内获认可。将失败原因推广为规则前，提出候选规则的适用条件、反例和待验证点。只有用户明确认可规则本身后，才修订对应规则版本。

当前格式允许在 `provenance` 等扩展字段保存规则 ID 和前后案例关系；尚无完整的规则—案例自动反向索引或可视化管理界面。现有查询是结构候选检索，不等于自动推理解决所有布线问题。

## 6. 交付与下一轮

保存可重开的 `.blend`、局部网格 JSON、检查报告、预览和用户评价。报告实际完成的层级。实际项目资产应在单独受控的项目目录保存；此仓库的四个样本只负责演示和复现。
